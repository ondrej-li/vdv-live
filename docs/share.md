# Sharing a vehicle or a stop's board

Two things can be shared from the app: the vehicle whose card is open, and the
departure board of the stop on screen. Both go through the system share sheet -
there is no custom sharing UI, no share extension and no account.

## What a share contains

A subject line, a message, and a link.

**A vehicle** — line, destination, delay, when the feed was read, and, when the
card's detail has loaded, the stop it was last seen at and the next one:

```
337 → Jihlava, aut.nádr.
+3 min · aktuální k 7:12
Naposledy Telč, aut.nádr. · příští Telč, rozc.
```

**A board** — the stop, the time the board was read, and its next five
departures, each with the time it leaves and its status:

```
Odjezdy ze zastávky Telč, aut.nádr. (7:12)
420 → Jihlava, aut.nádr. 7:18 (+2 min)
337 → Třebíč, aut.nádr. 7:24 (včas)
410 → Telč, rozc. 7:31 (podle řádu)
```

Five is [`ShareComposer.sharedBoardRows`](../VdvLive/Domain/ShareComposer.swift):
enough to show the shape of the next hour, few enough to stay one message.

The wording follows the app's language, like every other string, and the status
is spelled out (`podle řádu`, `včas`, `+3 min`) rather than left to a colour that
a message cannot carry.

## The links

| Shared | Link |
|---|---|
| A board | `https://vdv.ondralinek.cz/s/?stop=Tel%C4%8D%2Caut.n%C3%A1dr.` |
| A vehicle | `https://vdv.ondralinek.cz/s/?line=337&service=3` |

**With the app installed** the link is a universal link: iOS opens the app at that
board, or on that vehicle. `VdvLive/Features/Map/VehicleMapView.swift` answers it
in `openSharedLink(_:)`, which reuses the routing the reminder notifications
already use.

**Without the app** the same URL is a small page at `vdv.ondralinek.cz/s/` that
says what was shared and offers the app. It is generated by
`tools/build-site.py` with the rest of the site.

### A vehicle link outlives its vehicle

A bus finishes its run, and the feed names the line but not the run, so a shared
vehicle is found by asking each vehicle of that line for its service number. If
that service is no longer reporting, the app opens the line's traffic instead of
an empty card. A link that no longer resolves never fails loudly: the person
tapping it did not ask this app anything.

## What the server has to do

1. **`/.well-known/apple-app-site-association`** — written by `tools/build-site.py`,
   claiming `B592D69P29.cz.ondralinek.VdvLive` for `/s/*`.
2. **Served as JSON, never redirected, uncached** — `deploy/nginx/vdvlive.conf`
   has an exact-match location for it, because the file has no extension and
   nginx would otherwise hand it out as `application/octet-stream`, which iOS
   refuses.
3. **The `applinks:` entitlement** — `Config/VdvLive.entitlements`, which automatic
   signing turns into an Associated Domains capability on the app id.

The nginx file is not installed by `make site-deploy`: it is a server
configuration, changed by hand (and backed up) when it changes:

```sh
scp deploy/nginx/vdvlive.conf deploy@2.31.33.21:/tmp/
ssh deploy@2.31.33.21 'sudo cp /tmp/vdvlive.conf /etc/nginx/sites-available/vdvlive \
    && sudo nginx -t && sudo systemctl reload nginx'
```

## Checking it

```sh
curl -sSI https://vdv.ondralinek.cz/.well-known/apple-app-site-association | grep -i content-type
curl -s  https://vdv.ondralinek.cz/.well-known/apple-app-site-association
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' 'https://vdv.ondralinek.cz/s/?stop=Trebic'
```

On a device, the association is cached by iOS. If a link does nothing, the file or
the entitlement changed after the app was installed: delete the app, reinstall,
and open the link from Messages or Notes (not from a browser's address bar).

`VdvLiveTests/ShareComposerTests.swift` covers the text, the link shapes and the
parser, including links the app must not answer.
